# 2026-07-07 — HippyAgent 移动端交互系统优化

## 任务背景
用户希望优化并重设计一个"移动端 App"当前混乱臃肿的交互系统。项目 = **HippyAgent**（Android Kotlin + Jetpack Compose 原生 AI 智能体框架），UI 层在 `app/src/main/kotlin/com/lin/hippyagent/ui/`。

## 诊断（代码实证，5 点）
1. **导航 850 行上帝函数** `ui/navigation/AppNavigation.kt`：50+ 路由内联，同一 `onBackClick` 重复 30+ 次；`TaskList`/`NotificationCenter` 为"幽灵路由"只重定向到 Inbox。
2. **双导航并存、信息架构不清**：底部 `MainScreen` 4 页 pager + 全局 `NavHost`；设置以 `agent/{id}/xxx` 树挂在"会话"页第 3 页。
3. **聊天交互层碎片化成 10+ 各自手搓浮层**：AgentListDialog / ChatSessionDrawer / MessageActionsSheet / ModelSwitchSheet / PermissionRequestDialog / CreateDrawer / PlanPanel / ChatModeSelector / QueueBottomSheet / InlineApprovalCard / PrivateTurnCard 等，无统一 Sheet/Dialog/Approval 原语。
4. **状态源重复、控制流分散**：`AppNavigation` 自带 `TODO(W29/P2): currentAgentId 与 lastActiveAgentId 语义重叠`；`AgentSelectionHolder` 单例 + 两个本地 mutableStateOf。
5. **设计 Token 自相矛盾** `ui/theme/Theme.kt`：`NotionTypography` 被 `scaledTypography` 用对不上的硬编码值覆盖（死代码）；颜色命名 `WarmOrangeLight/Dark` 当深浅色 primary；无统一间距/圆角/阴影/动效标尺。

## 用户已确认的方向（AskUserQuestion 结果）
- **切入方向（全选）**：统一交互组件库+Token / 重做聊天核心体验 / 重构导航与信息架构 / 建立完整设计系统。
- **首要目标**：用户操作清晰度（减少迷失、路径更短、更可预期）。
- **交付形式**：核心界面高保真重设计稿优先，规范边做边沉淀。
